# Push and deploy

Use only when the user explicitly requests both delivery and deployment.

Follow `pushup.md` to review, validate, commit, push and create or update the PR. Inspect the repository's actual deployment configuration and available hosting tools. The README describes Vercel, but that alone does not establish a linked project, production environment or automatic deployment policy.

Identify the authorized project, environment and revision before deployment. Use the hosting provider's applicable instructions and tools. Do not install or configure a new hosting service merely to complete this workflow. If the deployment target cannot be established from the repo and request, finish independent preparation and ask for that missing target.

Verify the resulting deployment URL and the affected Home Logistics flow. Report the commit, PR, deployment URL and observed checks. Do not merge a PR or promote a preview to production unless that action is authorized.
